# 识途智能旅游规划 Agent

识途是面向自由行用户的交互式旅行规划原型。通过自然语言与可视化工作台协作，完成需求收集、景点选择、住宿位置、可选房型与往返交通、餐饮安排、旅行地图及计划书生成，并保存用户偏好、选择和版本。

当前为 v11 基础上的协作整合版，已接入 DeepSeek、高德地图、和风天气及途牛 MCP，适用于本机和小规模体验。计划包含建议安排与待确认事项，不构成实际预订、实时导航或全部事实已核实的保证。

## 功能与业务流程

1. 输入目的地、出发地、日期、人数、预算及偏好；缺少信息可通过对话补充或手动编辑。
2. 查询与比较景点，查看详情、图片、地图和景区分支；支持指定游玩日期与时段。
3. 比较住宿位置与房型报价，核对面积、餐食、人数、退改和查询时可售状态；支持暂不安排住宿。
4. 按需选择高铁、火车或航班并设置往返日期与时段；也可选择自驾或往返自行安排，无需强制选票。
5. 按日期与餐次逐项选择餐厅，保存后自动进入下一饭点，并按对应游览区域刷新候选；重点展示店铺特色、人均及营业资料，可随时修改或自行安排。
6. 生成每日计划，查询多种通行方式、计算时间与缓冲、校验冲突，并进行独立模型审核。
7. 查看、调整、撤销或导出计划；修改影响现有安排时标记旧计划待更新。

地图支持全国范围拖动、鼠标位置滚轮缩放、双击放大、百分比显示与中心复位；操作由 Canvas 即时响应，手势停止后更新高德底图。浮动小地图可拖动、收起和展开，景点/住宿/餐饮分色，并突出当前地点；详情地图聚焦当前地点。已取得道路坐标的日程以红色实线绘制实际查询路线，其他情况下明确显示顺序示意。

右侧悬停时间轴联动地点、住宿与餐次，日期时间可点击定位；正式计划前的顺序按位置、日期与时段生成，时长为估算，并不保证全局最优。计划生成时再查询道路耗时，校验交通边界；可变安排支持有限次修订，固定条件无法满足时显示可跳转警示。途牛缩略图优先尝试同源原图，加载失败回退，低清图不放大并保留完整比例。

账户支持注册登录、恢复码、个人数据导出和账户隔离。用户可创建、切换、重命名、归档及删除多次旅行。任务状态持久化，支持刷新查看进度、停止和重启中断标记。

## 技术栈与执行机制

| 层次 | 技术与职责 |
| --- | --- |
| 模型 | DeepSeek，Function Calling 意图识别、JSON 规划提案、SSE 流式回复与独立审核 |
| 业务编排 | LangGraph 的 understand 与 execute 主链，以及独立业务模块 |
| 后端 | Python、FastAPI、Pydantic、Uvicorn、HTTPX |
| 工具 | MCP Python SDK；本地 stdio MCP 提供高德、天气与资料检索，Streamable HTTP MCP 接入途牛 |
| 检索 | 官方资料父子块、BM25、FastEmbed中文向量、Qdrant余弦召回与RRF融合，保留来源/版本/适用范围 |
| 存储 | SQLite 保存账户、旅行、选择、版本、任务与有限期缓存 |
| 前端 | HTML、CSS、JavaScript、Canvas 与任务 SSE，无需前端构建 |
| 检查 | pytest 业务/API 检查与 Playwright 浏览器场景 |

模型返回业务动作、需求补丁与候选 ID，程序校验后执行。规划限定于已选 ID 和有效日期，长行程分阶段生成；路线耗时由工具提供，程序检查时间，审核模型复核遗漏。当前未采用 Redis、独立任务队列或完整高德 JS SDK。Qdrant支持本地持久化及服务端连接，多Worker部署须使用服务端。

## 本地安装与启动

使用兼容的 Python 3.11 或之后版本；便携包已验证 Python 3.13.9。Windows PowerShell 示例：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
Copy-Item .env.example .env
```

在本机编辑 `.env`，填写 DeepSeek、高德、和风和途牛配置。途牛可使用单个 `TUNIU_API_KEY`，或四个独立账号的 `TUNIU_API_KEY_1` 至 `TUNIU_API_KEY_4`；编号配置优先，按可用账号轮换，每个账号独立限速与计量。配置修改后重启服务。和风 Host 需要替换为账号实际分配的地址；仓库中的 `.env.example` 仅为占位模板，不包含可用密钥。

首次初始化中文模型与知识索引：

```powershell
.\.venv\Scripts\python.exe scripts/build_knowledge_index.py --download-model
```

后续正常检索不自动下载模型。没有初始化或索引过期时会明确降级为BM25；采集、更新与服务端部署说明见[数据服务文档](docs/collaboration/数据与知识服务接入说明.md)。

然后双击 `启动.cmd` 或执行：

```powershell
.\启动.ps1
```

浏览器访问 http://127.0.0.1:8767 ，首次使用注册账户并保存恢复码。手动启动亦可：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8767 --no-access-log
```

查询供应商接口需要网络与相应账号权限；缺少配置时按启动提示处理，不使用代码内置密钥。当前服务用于本机，正式公网部署仍需 HTTPS、访问域名、监控、共享存储及运行保障。

## 数据来源与能力边界

- 高德：地点、餐厅、营业资料、电话、人均、图片、地图与路线。营业资料不保证出游当天状态，人均不是门票价格。
- 途牛：酒店房型、往返交通与门票产品。区间最低价不等于当天准确报价，销售区间不代表可预约名额；选择与推荐不代表已预订。
- 和风：接口实际覆盖窗口内天气及当前预警；超出窗口的日期保留待确认。
- 官方资料：部分景区资料及城市概览。城市、规则及日期覆盖仍需完善，采集时间不等于未来适用日期。

支持 1 至 60 个游玩日，过密或跨度较大的选择会提示调整，但不保证全局最优排程。客流预测、自动支付/出票、完整预算尚未实现；逐晚住宿、时间轴工具调整及已查询接驳已接入，未知运营条件仍需核实。查询失败、无结果和字段缺失分别处理，不补造数据。

## 复核整合记录

v11.2已修复酒店地图候选只核对前三家、名称别名匹配失败及地址回填遗漏；旧住宿可更新位置，卡片与地图同步。加入餐厅、酒店及有参照区域的景点通行预检查，区分明确空方案与接口异常，未核实数据保留提示；完整计划仍须按最终顺序检查。验证包含148条后端测试、酒店地址/两处地图联动浏览器场景，以及3家真实酒店和餐厅路段的高德只读查询。

在v11交互功能基础上吸收fix/shitu-review-csp-meal-guard的审核字段兼容、高德图片来源和餐次前置校验，并统一到达缓冲、返程准备及完整用餐时长。组员提交保留在整合分支历史中。用户先选餐后修改交通时，相关餐次保留并标出冲突，不会自动迁移到其他日期；景点与餐次的显式跟随绑定尚未实现。
