## 用户已明确的要求

- 项目服务于不常旅游、做攻略费时费力的人，重点是可靠的信息及辅助决策。
- 项目使用 Agent、MCP、RAG；用户持有途牛 MCP、高德 API、和风天气与 LLM。
- 默认先选择景点，再按景点位置、交通和住宿环境推荐住宿；已有预订允许反向规划。
- 最终输出完整旅行计划书，支持修改；展示 HTML 全部模拟数据只表达理想交互。
- 考虑时间组合、购票/预约、交通方式、体力、预算和不确定性，查不到的不能编造。
- 项目不能太大；“模拟人”是探索性构思，并非必须采用的方案。多 Agent 可以加入审核，数量与具体分工尚未最终确认。
- 用户关心是否能边开发边实际使用检查，以及长对话上下文压缩导致方向偏离的风险。
- 用户要求真实项目页面重新按功能设计，不沿用旧 HTML 的结构与交互。
- 用户要求按正式公司项目建设：补注册登录、重开独立对话、历史旅行、权限和网站必要的配套功能。

## 第一版已采用的实现

- 小范围端到端迭代，知识库先覆盖青岛；日程最多5天、10个已选景点。
