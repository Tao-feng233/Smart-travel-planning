# P0/P1能力矩阵 v0.4

> 本文件是功能优先级的唯一裁决源。其他文档不得重新定义P0/P1，只能引用本矩阵。

| 能力 | P0必须完成 | P1后续优化 | P0验收方式 |
|---|---|---|---|
| 用户需求 | 自然语言生成合法TripProfile；关键缺失信息追问 | 长期用户画像 | 非固定表达通过Schema校验 |
| 知识覆盖 | CoverageSnapshot + 针对当前用户的ReadinessEvaluation | 自动覆盖质量评测 | 数据不足的目的地不进入候选 |
| 目的地推荐 | 仅在planning_ready候选中，带证据和取舍 | 多目的地组合推荐 | 越界ID被拒绝 |
| RAG | 认知知识语义检索，保留entity_id/evidence_id | 评论聚合和混合检索调优 | 推荐结果可回指证据 |
| MCP | 9个契约工具均有可调用实现，允许Mock | 更多真实Provider和工具 | 端到端留下目的地、资源、事实、路线四类调用日志 |
| 单目的地 | 一个城市/区域内多个游玩区域和地点 | 双目的地真实规划 | 生成覆盖全部日期的行程 |
| 抵达/离开 | 典型方式、门到门时间、价格区间、到站衔接 | 实时班次、票价、余票 | 无真实数据时不虚构班次 |
| 景点 | 位置、开放、预约、时长、费用、体力和证据 | 更丰富现场设施和人流 | 不可用地点被前置过滤 |
| 住宿 | 区域 + 至少一个人工整理候选；可用Mock | 实时库存、房型、退改和比价 | 不声称未验证候选可订 |
| 餐饮 | 具体店铺或用餐区域降级，插入每日时间轴 | 菜单、排队、预约和评论聚合 | 无数据时不虚构餐厅 |
| 本地交通 | 方式、门到门耗时、费用和步行负担 | 实时拥堵与多路线优化 | 行程时间包含TravelLeg |
| 天气 | 可用真实或Mock数据展示并生成准备提醒 | 自动触发重规划、历史天气 | Mock状态可见；缺失时标待刷新 |
| 行前准备 | 基于规则、活动和天气生成清单 | 更丰富目的地规则 | 不使用无来源LLM常识 |
| 预算 | Money、CostItem、BudgetSummary统一计算 | 更精确动态价格 | 总额可由明细复算 |
| 验证 | 前置、增量、全局三层验证 | 更复杂求解优化 | ERROR冲突不能标VALID |
| 重规划 | 通用流程，至少一种事件完成端到端验收 | 自动事件监控、更多策略 | 锁定节点不变并生成新版本 |
| 版本 | 每次修改保存版本谱系和差异 | 用户撤回界面 | preserved/changed/removed可追踪 |
| 最终攻略 | 七部分TravelGuide和Vue页面 | Markdown/PDF、地图 | 七部分存在，未知项显式展示 |
| 数据模式 | MOCK/SNAPSHOT/LIVE/HYBRID可切换 | 多Provider自动容灾 | 业务代码不依赖具体Provider |
| 模型Provider | 一个主模型接通，预留备用配置 | 自动故障切换 | 结构化输出和工具调用POC通过 |
| 部署 | 本地一键说明和可复现启动 | Docker Compose | README可让第三方启动 |

## 明确不在P0

- 全国或全球完整数据。
- 真实支付、出票、酒店代订。
- 三个以上目的地优化。
- 精确实时客流人数。
- 抢票成功率预测。
- 社区和原生移动端。
- 生产级长期数据维护平台。
