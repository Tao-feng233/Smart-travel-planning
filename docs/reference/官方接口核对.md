## 1. 途牛 MCP：已有服务直接接入

官方 [授权接入](https://open.tuniu.com/mcp/docs/guide/mcp-auth.html) 使用 Streamable HTTP，列出酒店、机票、火车票、门票等服务。服务地址分别是 `https://openapi.tuniu.cn/hybrid/mcp/hotel`、`/flight`、`/train`、`/ticket`。实际接入地址仍需与用户持有的服务核对。

官方支持 OAuth；具体采用 OAuth 还是 API Key，要按现有凭据类型确定，不自行猜测认证头。连接后执行初始化、`tools/list`，保存 schema 快照再实现调用适配。官方明确说明：“工具名称及参数结构以实时 tools/list 返回的 inputSchema 为准。”

### 酒店

来源：[酒店服务官方文档](https://open.tuniu.com/mcp/docs/apidoc/mcp/hotelMCP.html)。

| 工具 | 主要输入 | 可用于产品的输出 |
|---|---|---|
| `tuniuHotelSearch` | 首次必填 `cityName`；`checkIn`、`checkOut` 成对传入；可用 `keyword`、`poiName`、`prices`、`adultNum`、`childNum`、`childAges` | `hotelId`、名称、地址、评分、`lowestPrice`、点评概要、餐食和退改概要 |
| `tuniuHotelDetail` | `hotelId` 或 `hotelName`；日期对；可用 `roomNum`、人数和儿童年龄 | 酒店政策、评价统计、房型；房型下 `ratePlans` 包含 `rmbPrices`、餐食、退改、`count` 等 |

日期格式为 YYYY-MM-DD。没有日期会采用默认日期，项目应明确传用户日期。`prices` 是类似 `300-800` 的字符串。儿童年龄数组应与儿童人数一致。搜索翻页使用返回的 `queryId` 加 `pageNum`。

列表价格是起价，选酒店后应查房型。`rmbPrices` 的每晚/整段住宿、房间数量计价口径尚未通过实际响应验证。列表酒店字段未列经纬度，搜索响应中的 `poiInfo` 坐标属于搜索锚点，不能当酒店坐标。房型的 `preBookParam` 有 30 分钟有效期，这不是报价保价承诺。

### 国内机票

来源：[机票服务官方文档](https://open.tuniu.com/mcp/docs/apidoc/mcp/flightMCP.html)。

| 工具 | 主要输入 | 可用于产品的输出 |
|---|---|---|
| `searchLowestPriceFlight` | 必填 `departureCityName`、`arrivalCityName`、`departureDate`；可用 `searchType`、`departureTime`、`arrivalTime`、`priceRange`、`pageNum` | `flightNumber`、机场、起降时间、`basePrice`、`totalTax`、`cabinClass`、`remainingSeats` |
| `multiCabinDetails` | 先查列表；必填同一城市对、日期，以及 `flightNo` | 舱位报价、税费、购买条件、退改、行李、余座 |

搜索模式包含 `TIME`、`PRICE` 等，参数要按模式组合。翻页仍携带原城市和日期。列表的 `flightNumber` 对应详情输入的 `flightNo`，名称不同。搜索参数表未列成人/儿童人数，不能自行添加供应商参数或把成人价当已查实儿童价。余座返回为字符串，展示含义需结合实际值验证。

### 火车票

来源：[火车票服务官方文档](https://open.tuniu.com/mcp/docs/apidoc/mcp/trainMCP.html)。

| 工具 | 主要输入 | 可用于产品的输出 |
|---|---|---|
| `searchLowestPriceTrain` | 必填 `departureCityName`、`arrivalCityName`、`departureDate`；可用 `searchType`、出发/到达时间范围 | `trainNum`、车站、时刻、时长、分席别 `price` 和 `seatAvailable` |
| `queryTrainDetail` | 先查列表；必填 `departureStationName`、`arrivalStationName`、`departureDate`、`trainNum` | `trainInfo`、席别价格和 `leftNumber`、状态等 `seatInfo` |

`searchType` 是字符串 `1` 至 `6`，表示不同排序，不沿用机票的 TIME/PRICE。翻页用 `queryId` 和 `pageNum`。详情必须用车站名称，不能传城市名。列表价格空字符串、余票 null 表示对应席别不存在，余票 0 表示无票，应区别处理；没有总库存就不能算“剩余百分比”。

### 景区门票

来源：[门票服务官方文档](https://open.tuniu.com/mcp/docs/apidoc/mcp/ticketMCP.html)。

`query_cheapest_tickets` 必填 `scenic_name`，可选 `depart_date`。输出含 `productId`、`resId`、`startPrice`、`departsDate`、销售区间 `startDate/endDate`、票种与资源名称。

核心边界：日期筛选是销售区间覆盖指定日期；`startPrice` 是区间最低价，`departsDate` 是该最低价对应日期。因此可能不是用户当天价格。页面未列独立的只读“指定日期准确报价”工具。实时 `tools/list` 若没有额外能力，界面展示“起价”，预算标待核实，不能为取价格擅自调用创建订单。

该工具不能单独证明景区开放、预约名额或完整入园规则。这些规则应另查景区官方资料。

### 配额与工具范围

[官方限流页](https://open.tuniu.com/mcp/docs/guide/ratelimit.html) 列出：最多 2 个 API Key，每分钟 5 次、每天 50 次，所有 API Key 共享。这个描述需要与用户实际认证方式和账号额度对照，不能直接断定 OAuth 或所有接入渠道均相同。

项目使用查询工具白名单。官方还有创建/取消订单等工具，但旅游规划阶段不需要开放给模型。候选查询、详情展开、分页均消耗请求，应用须统一调度和统计，不能每轮对话刷新所有类别。

## 2. 高德 Web API：地点与通行计算

来源：[POI 2.0](https://developer.amap.com/api/webservice/guide/api-advanced/newpoisearch)、[路线 2.0](https://developer.amap.com/api/webservice/guide/api/newroute)。采用哪个版本要与账号权限确认；本表基于 2.0 文档。

| 能力 | 官方路径 | 关键参数 |
|---|---|---|
| 关键词搜索 | `/v5/place/text` | `key`；`keywords` 与 `types` 至少一个；城市用 `region`，严格限制配合 `city_limit=true` |
| 周边搜索 | `/v5/place/around` | `key`、`location`；可用 `types`、`keywords`、`radius` |
| ID 详情 | `/v5/place/detail` | `key`、`id`；最多 10 个 ID，用 `|` 分隔 |
| 步行 | `/v5/direction/walking` | `key`、`origin`、`destination` |
| 驾车 | `/v5/direction/driving` | 同上；可用 `strategy` |
| 公交 | `/v5/direction/transit/integrated` | 同上，加必填 `city1`、`city2`，使用高德 `citycode` |

地点基础字段含 ID、名称、地址、坐标和行政区信息。`show_fields` 控制商业信息、图片等附加字段；字段可能缺失。路线需按文档请求 `show_fields=cost` 获得耗时，单位秒；画路线还需请求 `polyline`。高德坐标参数是经度在前。

项目的适配边界：途牛 ID 与高德 ID 分开保存；酒店/景区需以城市、名称、地址匹配地点，歧义保留待确认。地点人均消费不是指定门票或酒店报价；地图营业资料不构成出游日期开放保证。路线耗时是工具预计值，排程还应单独留出等候和缓冲。

## 3. 和风天气：按实际版本适配

来源：[每日预报](https://dev.qweather.com/docs/api/weather/weather-daily-forecast/)、[当前预警](https://dev.qweather.com/docs/api/warning/weather-alert/)、[认证](https://dev.qweather.com/docs/configuration/authentication/)、[API Host](https://dev.qweather.com/docs/configuration/api-host/)。

| 能力 | 当前文档路径 | 参数与结果 |
|---|---|---|
| 每日预报 | `/weather/v1/daily/{latitude}/{longitude}` | 路径纬度、经度，最多两位小数；查询 `days` 为 1–10，默认 7，另有 `localTime`、`lang`；返回 `days[]`，温度、天气、风、降水等 |
| 当前官方预警 | `/weatheralert/v1/current/{latitude}/{longitude}` | 同样位置；可用 `localTime`、`lang`；返回 `alerts[]`，发布时间、有效期、类型、严重度等；`zeroResult` 区分成功无预警 |

Host 用控制台分配的地址。JWT 使用 Bearer；API Key 可使用 `X-QW-Api-Key`。只选择一种认证方式。用户若使用历史版本，需按该版本文档和响应做另一适配器，不能混用旧版字段。

当前每日预报不是任意日期查询：出游日期须落在返回窗口内。降水概率为 0–1，展示百分比要转换。默认 UTC，排程应统一时区。保存并展示 `metadata.attributions`。当前预警不等同于未来某日预警；查询失败与无预警必须区别。

## 4. LLM：已确定DeepSeek并验证所用能力

2026-10-05用户配置 `https://api.deepseek.com` 与 `deepseek-flash`。第一版使用工具调用识别业务动作、JSON模式生成与审核，通过实际账号验证。当前公开回复使用模型原生流式输出；意图与排程仍为后台工具调用/JSON，不声称JSON模式保证业务校验通过。

流式参数已核对[DeepSeek聊天补全文档](https://api-docs.deepseek.com/api/create-chat-completion/)：`stream: true`，读取SSE `choices[].delta.content`，以`[DONE]`识别完成；`stream_options.include_usage`取得用量。正文解析忽略原始reasoning字段。后端以任务SSE向浏览器传递已保存的增量，断开后可从同一任务继续读取。真实浏览器观察到任务未完成时多次增量更新，既有轮询保留为断开后的兼容路径。

## 2026-10-06 餐饮与交通日期补充

餐饮使用[高德搜索POI 2.0官方文档](https://developer.amap.com/api/webservice/guide/api-advanced/newpoisearch)：`/v5/place/text`或`/v5/place/around`，餐饮类型`050000`；周边查询传`location`、`radius`，不沿用文本搜索的城市限制参数。评分、营业资料、人均取实际business字段，字段缺失显示未知。市场按海鲜市场关键词查询并过滤餐厅类型，不补造采购或加工服务。

新增的去程/返程日期是本项目业务字段，不是供应商新参数：查询时仍分别传途牛已核对的`departureDate`。默认返程start_date+days，明确日期优先。真实只读查询验证了默认15日返程和改为16日后的班次；酒店与去程未被返程日期修改覆盖。

## 2026-10-07 地点父子关系

已再次核对[高德POI 2.0文档](https://developer.amap.com/api/webservice/guide/api-advanced/newpoisearch)：`pois[].parent`为父POI真实ID，可能为空；`show_fields=children`返回子POI的ID、名称、坐标、地址、subtype与typecode。父地点详情通过`/v5/place/detail`查询，最多10个ID，本项目每批最多补4个父地点。名称前缀只作待核实关联，不补造父ID。

## 2026-10-07 v10 补全核验
