# 数据与知识服务接入说明

## 本批完成范围

在v11.2整合版上升级MCP、资料采集和RAG，保持既有items与地点字段兼容。业务数据库仍为原实现；MySQL、独立Worker、JS地图和动态时间引擎由另外两个工作分支继续开发。

- 真实中文Embedding：FastEmbed + ONNX Runtime，默认BAAI/bge-small-zh-v1.5，512维；可切换兼容Embedding API。
- 向量检索：Qdrant命名向量dense，余弦相似度；当前电脑使用持久化本地模式，也提供QDRANT_URL服务端连接。
- 混合检索：中文字符二元组BM25 + 语义召回，RRF融合后按父块聚合，限制上下文预算。
- 分块：优先按段落、中文句号等边界切分，父块最多1400字符；子块最多360字符、适用时重叠50字符。过长单句再按长度切分。检索子块，返回对应父块、命中片段与来源，避免只返回脱离条件的短句。
- 资料治理：来源注册表、正文选择器、内容版本、采集状态、适用日期、实体标识及历史快照；失败不覆盖有效正文。
- 交通地点：新增车站/机场坐标候选工具，为接驳计算提供输入；未接入自动交通排程。

Qdrant本地模式由Python客户端实现，适合开发与单进程验证，并非已部署Rust服务端。多人/多Worker共享查询时由成员二启动Qdrant服务，随后设置连接地址并重建索引；不能让多个进程同时打开同一份本地数据库。

## 初始化与更新

在仓库根目录安装requirements-lock.txt，配置示例见.env.example。首次允许下载模型的命令如下；正常检索不会自动下载模型。

```powershell
.\.venv\Scripts\python.exe scripts/build_knowledge_index.py --download-model
.\.venv\Scripts\python.exe scripts/check_data_service.py
```

更新流程：

```powershell
.\.venv\Scripts\python.exe scripts/collect_knowledge.py
.\.venv\Scripts\python.exe scripts/build_knowledge_index.py
```

采集命令出现部分失败时返回非零，保留成功来源及失败来源的旧正文并记录报告。查看data/runtime/knowledge-collection-report.json，确认来源范围后再建立新索引。索引按版本建立新集合，完成写入和数量核对后原子切换manifest；异常保留旧manifest。正文已更新而向量尚未更新时，明确降级为BM25，不混用旧向量。

模型缓存、向量文件、历史归档及验证记录均在忽略提交的data/runtime中。原文与公开注册表可以提交；个人配置和业务记录不进入GitHub。

切换服务端：设置QDRANT_URL，例如本机服务的http://127.0.0.1:6333；有认证时设置QDRANT_API_KEY。重新运行build_knowledge_index.py，不能把本地manifest直接当作服务端已建集合。服务端不可用时检索明确降级，不伪造语义结果。

## 成员二：存储与Worker对接

| 数据对象 | 当前实现与接入要求 |
| --- | --- |
| 原始文档 | data/knowledge/*.json；保留id、city、title、url、text、fetched_at、scope/date_scope、source_kind |
| 内容版本 | source_version是正文摘要，previous_version记录上次内容版本；同文档更新替换有效版本，历史归档独立保存 |
| 父子索引 | app/knowledge.py产生parents与children；parent_id用于回取上下文，content_version用于追踪内容 |
| 索引状态 | app/vector_index.py维护manifest，包含语料摘要、模型身份、后端身份和集合名 |
| 地点质量 | 原字段保持兼容，新增_data中的schema_version、GCJ-02、未知字段、查询时间与日期适用状态 |

迁移MySQL时，将文档加载/发布适配到KnowledgeRepository，保持上述身份和版本语义；Qdrant只存子块向量与查询所需载荷，原文/父块由Repository保存。不要在platform分支另写切分和Embedding逻辑。原文修改、资料采集与索引构建需要可重跑阶段；当前显式CLI更新不等同于后台自动任务已经完成。

app/data_settings.py仅管理数据侧配置，兼容环境变量和现有.env；平台统一配置时合并这些字段。app/data_contracts.py是本批数据字段辅助模块，与拟建公共contracts.py分别承担数据和业务契约，后续可共同整理。

## 成员三：规划与时间对接

MCP接口保持字典返回：

```json
{
  "tool": "retrieve_guides",
  "arguments": {
    "city": "成都",
    "query": "熊猫基地开放与轮休规则",
    "visit_date": "2026-11-10",
    "end_date": "2026-11-12",
    "limit": 5
  }
}
```

visit_date单独使用表示一天；搭配end_date表示区间，按适用日期交集过滤。entity_ids可选，采用严格交集；没有人工核对的实体ID时不要填写猜测值。已在discovery与planning中通过guide_conditions传递旅行日期范围；用户指定景点日期后，可逐景点调用以缩小资料适用范围。

返回items之外有status、retrieval、degraded_reason、corpus_version；各条有matched_texts、lexical_score、dense_score、validity与context_truncated。业务仍可以读取items，但必须保留适用提示：

| 状态 | 含义 |
| --- | --- |
| background_only | 仅作为景点特色和文化背景，不能证明当前运营 |
| stale_snapshot | 旧采集快照，后续检查失败或页面变化，规则待复核 |
| visit_date_unverified | 当前资料没有足够日期依据，不能保证未来适用 |
| within_declared_scope | 日期与已声明范围有交集；仍不是实时库存保证 |
| degraded | 语义索引不可用/过期，已使用BM25；查看降级原因 |
| query_failed | 格式或条件无效，与查询成功无结果不同 |

临时公告没有明确查询日期时不参加召回。旧崂山10月5日限流公告已限定该日，不能在10月12日查询中作为当前事实。

接驳候选接口：search_transport_places(city, keywords, kind="station"或"airport", include_access_points=False)。返回实际POI ID、位置、出入口、城市代码、来源及endpoint_scope。所有候选均标match_status=candidate和terminal_confirmed=false；选择同名站点或确认机场航站楼仍由业务层处理，不能直接取第一项作为确定端点。

calculate_route保持原有available/status/minutes/source与道路折线。no_route、query_failed、missing_city、incomplete须分别处理；查询异常不是道路不通，未知接驳也不能按零分钟参与规划。

## 验收与边界

自动回归覆盖父块条件、重复资料、城市/日期/实体过滤、真实Qdrant本地持久化、后端切换、更新失败保留旧索引、采集失败保留正文、API向量序号检查及交通地点类型过滤。check_data_service.py通过真实stdio MCP、实际中文模型与Qdrant核对召回；--live-poi额外调用高德车站/机场查询，会使用接口额度。

语料覆盖仍有限，不代表全国运营规则齐全。当前新增成都、杭州和西安官方正文，青岛保留来源明确的旧快照及背景；没有实现泛联网搜索、新闻客流预测或自动推导所有临时公告的生效日期。相似度阈值默认0.58是当前验证参数，扩大语料后应通过评测调整，不把分数当正确率。
