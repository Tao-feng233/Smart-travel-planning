# 成员二任务说明

负责Agent与业务系统升级，完成MySQL持久化、独立后台Worker、明确日期语义和高德JS API联动。范围是单机可运行的业务功能，不扩展为集群或完整企业平台。

源码基线为仓库 `Tao-feng233/Smart-travel-planning` 的 `feat/shitu-v11-review-integration`，已完成代码提交为 `40374bc590bedefd78e03b759f61d7c9b1ddeb82`。该版本已包含酒店位置恢复和候选通行预检查，后端基线为148条测试。本文描述平台待开发工作，MySQL、JS API和新的时间引擎尚未接入。协调者已推进Qdrant与数据服务，接入说明见[数据与知识服务接入说明](数据与知识服务接入说明.md)。

从包含本说明的最新整合分支创建工作分支，建议名称 `feat/shitu-v12-platform`。不要从旧main或体验ZIP开始。所有文件路径相对于仓库根目录。

## 第一批 先提交公共接口

先提交一份较小PR，定义存储接口、任务上下文与日期字段，不急于改完所有业务。接口可以按下表命名，也可提出等价方案；通过评审后，其他两人基于同一契约开发。新接口在合并前是设计约定，不是现有功能。

| 接口能力 | 必须表达的语义 |
| --- | --- |
| WorkspaceRepository | 按owner读取；按expected_revision保存；版本冲突不能静默覆盖；支持快照和撤销 |
| CacheRepository | 参数键、过期时间、查询结果；保留当前缓存口径 |
| ProviderBudgetRepository | 原子记录和检查供应商调用；从providers里移出直接SQL |
| JobRepository | 幂等提交、互斥领取、租约、取消、完成/失败、进度和阶段结果 |
| KnowledgeRepository | 原文/父块、doc_id、版本、来源、城市、实体ID、适用时间及索引状态 |

约定任务上下文至少提供 `job_id`、`is_cancelled()`、`emit_progress()`、`load_stage()`、`save_stage()`。模型提案、工具查询和规划阶段可以据此复用已完成结果。

时间相关字段要区分用户明确输入、班次事实和系统建议。区分游玩日期、去程日期、返程日期；没确认的建议必须保留确认状态。具体字段名先与成员三对齐，不能两个分支各写一份TimeProfile。

公共契约建议集中到新增 `app/contracts.py` 或等价目录。本人牵头存储与任务部分，成员三提供时间与时长部分；协调者审核后合并同一份定义。其他功能可以先使用契约对应的测试夹具开发。

## 第二批 MySQL与独立任务执行

### MySQL业务存储

使用SQLAlchemy等统一数据访问层与版本化迁移。账户、登录、任务、缓存、调用预算和版本保留独立记录；旅行正文可先保留JSON快照，不要求本期拆完所有实体。

替换所有直接SQLite依赖，包括main中的事务、auth中的查询和providers中的预算/缓存访问。统一连接与事务、日期时区、游标结果、唯一键和异常处理，不能只把数据库地址换成MySQL。

旧SQLite数据如需迁移，采用独立导入命令，源库保留；不得启动时自动清空或覆盖现有记录。使用合成数据测试，校验ID、账户归属、选择、版本、任务和缓存。真实数据库、配置和导出文件不提交仓库。

配置应支持环境变量及本地配置，补充空白 `.env.example`。知识文档与Qdrant向量的生命周期由协调者负责；本人提供原文和元数据的存储接口、迁移基础，并共同确认doc_id与版本规范。

### 后台Worker

API只提交任务，独立Worker从MySQL领取执行，SSE读取持久化进度。单机任务表与独立进程足以完成本期功能，无须另外引入消息平台。

任务状态至少包含queued、running、completed、failed、cancelled、interrupted；通过事务与租约防止重复领取。Worker崩溃后可接续未完成任务；保存可复用阶段，不把“重跑整轮模型调用”称为恢复。

先覆盖查询结果和行程提案的阶段复用；与成员三对齐路线/排程阶段接口。取消后不能再提交最终计划。规划失败保留原选择；写入计划时检查旅行版本，防止旧任务覆盖新的用户要求。

当前LangGraph未配置Checkpointer。若采用应用级阶段存储，写清其恢复边界；不要直接使用只适用于PostgreSQL的Saver接到MySQL上。每个可恢复阶段都要考虑重复执行和幂等。

## 第三批 日期理解与地图集成

### 日期与状态

支持明确区间、跨月和跨年、单独班次日期、景点指定日期以及跨日到达。明确区间包含首尾日；未明确年份或“玩3天”的出发日期，必要时询问，不能补造。

取消将“游玩结束次日返程”直接写成用户确定条件的做法。未确认返程由规划提出建议或保持未知；已有明确返程必须保留。对旧记录不能无依据覆盖已选车次或原日期。

本分支负责识别和保存时间意图；到达后何时可玩、返程前何时结束，由成员三的统一时间引擎计算。不要在journey、main或地图代码新增另一套90/120分钟规则。

### 高德JS API

将当前静态底图加Canvas相机替换为JS API，保留主地图、详情地图和浮动小地图，包含收起后拖动、全国缩放、中心复位、分类颜色、当前地点突出和已查询路线红线。

继续通过服务端MCP查询地点/路线，避免SDK与后端各查一套不同方案。SDK负责地图交互与绘制，路线顺序来自成员三；底图更新不修改旅行条件。组件复用实例，避免每次render重新创建地图。

需要新增JS API Key及安全密钥，目前项目仅有Web服务Key。协调者提供配置，由本分支处理加载和服务端安全代理；不将Web服务密钥下发到浏览器。CSP只放行SDK实际需要的来源，保留现有安全检查。

缺少Key时显示明确配置状态；如果保留旧地图降级模式，要注明模式，不能让验收误以为SDK已成功加载。

## 验收条件

| 场景 | 必须达到的结果 |
| --- | --- |
| 两个同request_id提交 | 返回同一任务，不重复执行 |
| 旧revision保存 | 拒绝冲突，不覆盖新选择 |
| Worker执行中退出并重启 | 恢复未完成任务，已保存查询/提案不重复调用 |
| 查询失败与取消 | 原选择保留；取消后无最终覆盖 |
| 12日至14日与独立返程15日 | 3个游玩日和返程独立，不因修改返程覆盖开始日期 |
| 跨午夜到达 | 保留完整日期时刻，不只截取HH:MM |
| 地图主/详情/浮窗 | 同一组已选地点，当前点突出，路线来自保存结果 |
| 日常启动 | 本机可以按文档启动MySQL、Qdrant、API及Worker，数据卷保留 |

测试覆盖MySQL事务与Worker真实边界；使用本地测试实例和合成数据，不依赖团队个人历史。保留原有148条测试的覆盖意义，必要时适配Repository测试夹具，不删除失败用例来通过检查。

## 如何与协调者通过GitHub对接

分成公共接口、存储/任务、日期/地图三个可验证批次，可在同一工作分支用独立提交组织。每批提交到GitHub，创建目标为 `feat/shitu-v11-review-integration` 的PR，或提供明确commit对比链接；不要直接覆盖整合分支或推main。

PR描述写明：基线、已完成范围、需要协调者接入的接口、数据库迁移与启动命令、验收结果、未完成项。新增依赖固定可安装版本，配置只提交空模板；个人密钥、数据库、截图、dist和备份均排除。

负责人将PR或compare链接贴到当前Codex会话，由协调者检查变更、运行验收、处理共享文件冲突并整合。本期协作以GitHub提交和负责人转交链接为准。

协调者合并公共接口后，先同步整合分支再继续后续批次。接口需改时，在PR说明输入/输出变化及受影响调用，不单方面重命名、删除字段或覆盖他人文件。

官方参考：[高德JS API配置](https://developer.amap.com/api/javascript-api-v2/guide/abc/jscode)、[MySQL队列领取相关锁定读取](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。
