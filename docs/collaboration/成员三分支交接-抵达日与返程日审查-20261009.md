## 二、本次新增什么

### 1. 按真实承运方写法修正含早识别（这是"含早没体现"的根因）

实测途牛房型餐食文本是 **「2份早餐」「1份早餐」「无早餐」**，而识别词只有
「含双早」「含早」「双早」这类写法：

- 「2份早餐」被判成 **1 份**（份数识别不到）
- 不含"早"字样的「含餐」压根不匹配

修正内容：

- `MEAL_INCLUDED_PATTERNS` 纳入「份早餐」等真实写法
- 新增 `MEAL_BREAKFAST_WORDS`：只提「含餐」「含正餐」时判为**未说明**，
  不替用户把正餐当成早餐（与整合版"泛指含餐误判"的修法方向一致）

| 输入 | 修正前 | 修正后 |
| --- | --- | --- |
| `2份早餐` | 含早 1 份 | 含早 **2 份** |
| `1份早餐` | 未说明 | 含早 1 份 |
| `含餐` / `含正餐` | 含早 | **未说明** |
| `无早餐` | 不含早 | 不含早 |

### 2. 新增 `app/travel_review.py`：抵达日与返程日审查

住宿夜晚本身已由 `stay_plan.nights()` 覆盖（提前抵达日计入、返程当天不计）。
本次补的是**"为什么这天没有住宿""抵达当天还赶不赶得上午饭"的明确说法**，
否则看起来像系统漏排了。

| 规则 | 行为 |
| --- | --- |
| 返程早于中午 12:00 | 明确说明当天不再需要住宿、这一晚已剔除；**未确认的班次不触发** |
| 提前抵达日（去程早于开始游玩日） | 那几天同样需要住宿与用餐，且以**抵达车站/机场**为中心 |
| 提前抵达日的时间 | **只安排地点、不写具体时刻**；午餐仅在 **15:00 前抵达**时安排，更晚跳过并说明原因 |

配套改动：

- `stay_plan.day_closure()`：提前抵达日改用抵达车站/机场作锚点（拿不到坐标时按站名兜底，
  因为 `poiName` 查询本身不需要坐标），并标明"坐标尚未核对"
- `agent` 的 `select` 分支：选定班次后调用审查，把结论附在回复里
- `stay_plan.hotel_for()`：提前抵达日尚未选酒店时，以抵达地点兜底返回一条住宿条目
  （`arrival_area: true`），避免那一晚在时间轴上完全没有住宿条目、看起来像漏排；
  已选酒店时仍以已选为准，普通游玩日不受影响

### 3. 我特意没有重复做的部分

`stay_plan.nights()` 在整合版里**已经**用 `start = min(start, arrived)` 处理了
"提前抵达日计入住宿"，所以新分支没有重复实现这一条，只补了锚点与提示。
