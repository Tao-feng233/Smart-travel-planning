# 语义任务执行与查询提速说明

更新日期：2026-10-08。本轮改动基于组长当前整合版本，未引入成员二的 MySQL / Worker 分支。

## 任务理解与执行

此前的对话流程主要由一次意图识别决定一个动作，再按工作台阶段生成回复。新流程首先输出语义任务 `mission`，区分方案咨询、事实查询、授权代选、计划修订、解释和用户明确选择，同时记录目标、范围、是否需要连续执行及是否生成计划书。工作台阶段仅作为上下文；具备有效语义任务时，不再通过旧关键词规则覆盖用户意图。旧结构保留兼容入口。

`app/goal_agent.py` 负责保存任务状态和工具观察。多步骤查询在首项操作完成后，将真实结果、错误、当前条件、候选与精简计划交给模型，由模型选择下一项工具或结束。每轮最多四次后续决策；重复查询、非法操作及参数越界会受到限制。上下文包含每日活动、日期、时段、地点 ID、实际转场时长和已有冲突，避免仅凭计划标题判断。

连续查询仅开放景点、酒店、餐厅、天气、详情、门票和交通查询等受控业务能力。选择、替换需要转入确认窗口；班次只能查询，由用户自行选定。计划修订仍走已有完整规划与校验流程，不允许查询循环直接写入计划。

## 决定范围与确认

泛化委托表达使用语义判断，不依赖新增某个固定句子的匹配规则。助手可以请求补齐剩余内容或重新选择，也可以在用户授权后选择目的地。尚缺日期、天数、人数时，确认窗口展示可修改的建议值；这些值在确认前不作为用户事实保存。

用户在委托中明确提供的条件需要对应本轮原文依据，并推迟到确认后采用。更换目的地的影响会在窗口说明，确认前保留原有景点、住宿与交通。咨询、解释或仅查询不能保存选择；与已有选择冲突的另一套旅行条件会要求澄清用途，当前暂不支持在同一旅行中同时保存两套对比方案。

住宿以选定酒店位置为完成条件，房型为可选。自动配置默认选择酒店，不强制查询或选择房型；补齐模式保留已有有效酒店。用户主动选择具体房型时仍执行人数、房间数与可售状态检查，未选房型不阻止规划。

任务状态包括运行中、等待确认、已完成、需要信息和部分完成。数据缺失或工具失败不能据此宣称已完成全部需求。已批准的自动配置仍支持停止和分批续跑。

## 查询延迟优化

1. **重复请求合并**：相同条件的高德、途牛查询及模型推荐在同时发生时共享一次实际请求。各调用者获得独立结果副本；取消一个等待者不会取消其他等待者的共同请求。
2. **HTTP 连接复用**：高德、天气与模型调用复用当前进程和事件循环中的连接池，在应用及 MCP 生命周期结束时关闭，减少反复建连。
3. **推荐缓存**：按旅行 ID、模型、查询条件、候选事实及资料建立十分钟缓存。用户改变条件或来源事实时重新计算，排除上一次推荐的派生字段，避免同一结果自身造成缓存失效。
4. **减少重复模型调用**：单一查询可直接使用业务结果回复，多步骤查询结束后直接使用任务完成回复。具备语义任务时取消无关的自动天气补查；不减少正式规划所需的事实核对。
5. **提前显示基础资料**：景点、住宿、餐饮资料到达后，通过任务进度传送当前旅行的候选预览，随后补充推荐和通行核对。最终保存仍以完整任务结果为准，预览不会覆盖已选地点。任务处理中选择按钮仍保持禁用。

途牛的供应商限流及现有项目预算继续保留，未并发绕过限制；冷查询、首次数据查询和实际路线核对仍可能需要等待。当前没有生产环境的整体耗时对比，不宣称所有查询已经缩短到某个固定秒数。

## 协作接口

- `assistant_goal`：旅行中的本轮目标、范围、状态与工具观察；后续平台迁移需要随旅行内容保存，不必建立单独任务队列。
- `pending_auto_selection.proposed_requirements`：等待确认的条件；前端可编辑日期、天数、成人数，后端校验确认编号、过期时间和旅行签名后采用。
- `job.ui.workspace_preview`：当前任务的候选目录与查询快照。前端仅接受当前旅行 ID 的预览，保留已选内容；任务结束后完整旅行结果替换预览。
- `app/request_cache.py`：每进程的短期请求合并与 HTTP 连接池。Worker 接入后也应在自身生命周期内关闭；供应商限流跨进程协调仍属于平台侧工作，进程内合并不等于分布式限流。

## 验证范围

后端完整回归 236 项通过，覆盖语义委托、只读边界、确认前条件保留、连续工具观察、请求合并、等待者取消隔离、连接复用及推荐缓存失效。浏览器验证确认窗口、可编辑建议日期、基础候选提前显示、跨旅行预览隔离，以及已有地图、历史和票务展示。

配置中的真实模型通过三种意图表达验证，并在合成供应商结果的工具流程中继续查询、调用结束工具，正确保留未知天气的缺项状态。该项验证调用了真实模型，但旅游供应商结果使用隔离夹具，不代表所有真实供应商组合已经完成端到端验收。验证记录保存在忽略的 `data/runtime/`，未修改用户历史数据库或上传 `.env`。
