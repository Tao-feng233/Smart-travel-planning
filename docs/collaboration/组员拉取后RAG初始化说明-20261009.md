# 拉取项目后的 RAG 初始化说明

日期：2026-10-09
同步分支：`feat/shitu-v11-review-integration`

## 1. 哪些内容已经推送？

RAG 检索代码、`data/knowledge` 下的知识资料，以及索引构建脚本都已经提交。

**向量索引、Embedding 模型缓存和个人 `.env` 不随 Git 同步。**这些是每台电脑自己的配置或生成文件。因此，拉取代码后，还需要在本机初始化 RAG。

## 2. 拉取后怎么操作？

先同步上述分支，保留并使用自己的 `.env`。以下命令都在项目根目录的 PowerShell 中运行。

如果尚未安装依赖，先运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

**第一次使用，或本机尚未下载中文向量模型：**

```powershell
.\.venv\Scripts\python.exe scripts/data/build_knowledge_index.py --download-model
```

**已经有模型，只更新知识索引：**

```powershell
.\.venv\Scripts\python.exe scripts/data/build_knowledge_index.py
```

建议先停止本机项目，构建完成后再启动。初始化只建立检索索引，不需要删除用户旅行数据库，也不需要重新采集知识资料。

## 3. 怎么判断成功？

命令正常结束，返回包含 `generation`、`records`、`children` 等字段的 JSON，且没有 `status: failed`，表示索引已建立或已是最新状态。`rebuilt: false` 表示无需重建，属于正常结果。

默认生成位置：

- 向量索引：`data/runtime/knowledge-index/`
- 中文模型缓存：`data/runtime/embedding-models/`

如果 `.env` 配置了自定义路径或远程 Qdrant，就按该配置建立索引；切换后也需要重新运行构建命令。

## 4. 常见情况

- **模型未就绪或首次下载失败**：检查网络，再运行带 `--download-model` 的命令。正常运行项目时不会自动下载模型。
- **拉取了新的知识资料**：再运行一次普通构建命令，然后重启项目。
- **未初始化或索引过期，但项目仍能查询资料**：这是降级为 BM25 关键词检索，不代表向量检索已经正常，推荐效果可能与其他电脑不同。
- **配置了远程 Qdrant**：确认服务可连接；本地生成的索引不能直接视为远程服务已有索引。

初始化失败时，请提供构建命令输出中不含密钥的信息，方便排查。不要把 `.env`、用户数据库或整个 `data/runtime` 上传仓库。
