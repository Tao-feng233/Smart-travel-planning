# 后端职责与目录整理（第二批）

本批整理后端结构，延续第一批的状态修复，不新增模型编辑策略。

## 完成内容

- 原来散放在后端根目录的 57 个模块按职责迁移。`app/` 根目录只保留 `main.py` 和包入口；模块分类见 [后端导航](../../app/README.md)。
- `main.py` 从约 435 行缩至 60 行，负责路由组装与外部资源生命周期。HTTP 接口位于 `api/`，后台任务执行位于 `application/jobs.py`，工作台数据整理位于 `application/workspaces.py`。
- 任务执行、取消和关闭共用一份状态注册表。账户隔离、请求幂等、并发和每日次数限制、任务 SSE、导出与安全响应头保留原行为。
- 共享 `DataError` 移至 `core/errors.py`，业务模块无需为导入错误类型而依赖供应商实现。供应商代码仍使用同一个错误类。
- 同步源码、测试和维护脚本导入路径，删除旧位置的实现，不保留重复业务副本。
- 统一后端格式，格式化前后 89 个模块的语法树一致。移除一个确认无调用方的检索导入；没有删除检索能力。
- 修复一个日期随运行日漂移的测试：固定该场景的模拟日期，保留生产代码“拒绝过去日期”的校验。

## 不变的运行条件

启动方式仍为根目录 `启动.cmd` / `启动.ps1` 或 `app.main:app`。

根目录 `.env`、SQLite 数据库、模型缓存和知识索引路径保持不变；前端资源、目的地目录和知识资料未改动。提示词模板文字未改动，动态上下文仅同步业务模块导入路径。

MCP 子进程入口改为 `app/integrations/mcp_server.py`，启动与数据检查脚本已同步。对接旧模块路径的后续分支需要按后端导航更新导入；本批尚未形成 GitHub 发布版本。
