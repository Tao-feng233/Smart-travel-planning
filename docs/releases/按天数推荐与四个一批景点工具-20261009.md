# 按天数推荐与四个一批景点工具

日期：2026-10-09
分支：feat/shitu-v11-review-integration

## 修复原因

旧覆盖校验只检查显式地点名，青岛官方背景正文已有的花石楼、中山路、奥帆中心等未登记到实体索引，被误排除。继续推荐还沿用同一个地图查询的后续页，在更换主题后容易得到空页。模型只返回一个排名时，程序也会只发布这个排名集合，使有效候选从多个缩成一个。

## 当前行为

- 初次推荐目标为天数×2：两天至少4个，三天至少6个；无天数按4个起步。单轮技术上限24个，长行程按阶段比较。
- 用户要求更多时模型可传 recommend_count（4–24）；继续推荐默认补充至少4个新的候选。
- 新的真实MCP工具 get_spot_candidates 每批最多4个，返回 next_offset、exhausted、位置排除及查询失败信息。业务在候选不够时继续获取下一批，不要求用户每次手动继续。
- 先从已覆盖的地点记录查地图名称，主题用于排序；不再直接把“休闲、公园”等泛词当地点名称后翻旧页。每次重新比较按当前主题从首批开始，排除已看过、已选和不感兴趣地点。
- 模型排名只影响展示顺序，有效未排名候选仍可比较；不因此删到一个。父子地点通过已有地图关系去重后再判断数量。
- 确实只有少量入库/定位/通行有效地点时，明确说明目标及实际数量，不虚构补齐。候选和备选不等于全部必须安排进时间轴。

## 数据边界

只给原有三条青岛官方背景记录补充正文中明确出现的 entity_names，没有新增城市、文章或臆测景点。名称校验统一处理城市前缀及常见景区/公园后缀，仍不进行模糊父子等同。未入库地区/地点继续保留缺失提示。位置未核实的候选不发布。资料正文、来源、采集日期和适用范围保持原样。

实体元数据更新后已使用本地模型重建Qdrant索引：90条原始记录、78父块、181子块；没有下载模型或改动用户旅行记录。

## 验证

- 382项后端测试通过，包括数量保底、模型只排名一个、真实MCP工具注册、4+2分批、换主题从首批重新获取、已选保护、坐标/辅助设施筛选与接口失败区分。
- 推荐卡片浏览器回归通过。
- 真实高德查询第一批4个、第二批4个，全部有坐标；业务按三天收集并按父子关系去重，保留7个候选，达到至少6个目标。
- 第一次冷查询两批约20.76秒；复用地图缓存后业务数量检查约2.6秒（含进程启动），不包含真实模型推荐与完整通行核对，不能视为所有用户操作的固定耗时。
