# 动作分发与任务执行重构

本批重点是整理代码内部结构，方便后续继续优化提示词和排程。已在本机接入；尚未推送 GitHub。

## 主要变化

- `planner.handle` 从 809 行缩到 17 行，负责提供依赖并转交动作，不再混放所有业务分支。
- 38 个动作归入景点、住宿、交通、餐饮、地点详情、旅行信息、规划和委托执行八类处理模块，位于 `app/travel/handlers/`。旧入口中的对应实现已删除。
- `jobs.perform` 从 449 行缩到 94 行，保留任务生命周期和异常处理；进度发布、前后状态比较、预演审核、回复收尾各有明确职责。
- 查询和选择动作的回复策略集中到 `action_policy.py`；状态比较统一使用 `turn_state.py`，删除重复定义。
- 旅行条件只由业务处理更新一次，移除了后台入口的重复更新。外部工具、模型和规划回调通过显式依赖传入动作处理。
- 清理搬迁后无用的导入和局部变量。前一步调整已提交、后续处理失败或取消时，也能结束任务并保存已完成部分，避免异常收尾再次报错。
