# 模型编辑工具与连续执行（第三批）

本批接通模型实际调用的编辑工具与连续执行链，保留查询 MCP 的职责与现有供应商接口。

## 行为变化

- “编辑计划”不再被强制转换为立刻生成计划。多步修改、生成或查询可根据实际结果继续调用工具，缺少景点时可以查询、选择后再生成。
- 工具组新增旅行状态观察、条件/偏好更新、选择/取消/替换、按夜晚修改住宿、按餐次修改餐饮、时间轴调整、生成/修订、跳过住宿、可选房型和撤销。
- 意图标签用于权限与上下文，不再阻止查询、选择、修改和生成衔接。查询、比较和说明不会获得选择修改权限；班次修改限定于本轮明确指定的 ID 和方向，整体委托保留已选交通。
- 用户明确委托且所需条件已经齐全时直接安排；需要采用日期、人数等默认假设时才保留确认方案。代选部分失败或尚有批次时可继续工具处理；完整成功的代选不额外增加模型决策轮次。
- “补齐剩余”不再因为已有一个景点而跳过景点补充；保留旧选择并补选适合行程的候选，不为凑数量强塞活动。一日游代选也允许当晚住宿。
- 主意图合同补齐每日开始/结束时刻、逐晚住宿字段、跳过住宿与撤销。取消景点同步清理指定日期与顺序；取消餐厅同步清理对应餐次。
- 对话中的撤销使用本轮开始前的版本，避免只撤销保存用户消息的那一步却没有恢复选择。

## 状态提交与实际结果

每项编辑先在工作区副本中执行，成功才提交。失败替换、失败生成和取消当前操作不会留下半完成的选择或覆盖原计划；此前已成功的步骤保留。一次消息内的增删选择作为一组提交。

查询过程仍可展示本任务的候选预览，通过任务局部上下文提供事实，不预先展示或保存未提交的选择。查询失败的状态标记保留，旧资料与选择保留。

每次模型决策都收到真实工具结果，参数按工具 Schema 校验。状态发生变化后允许重试同一操作；同状态重复调用和连续无效调用会停止。执行循环最多 10 次决策，整体任务沿用既有超时与并发限制。计划书未生成、仍待确认、还有未完成批次或未解决的代选住宿/餐次时，不能标记整体完成。

主要实现：`app/agents/edit_tools.py`（合同与编辑适配）、`execution.py`（连续决策）、`goals.py`（意图与观察）、`app/travel/actions.py`（提交边界）、`app/application/jobs.py`（后台任务入口）。旧连续查询循环和原零散增删路径已被替换。
