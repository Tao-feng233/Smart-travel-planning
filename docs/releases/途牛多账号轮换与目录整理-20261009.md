# 途牛多账号轮换与目录整理

日期：2026-10-09
分支：feat/shitu-v11-review-integration

## 使用当前四个 Key

根目录 `.env` 使用 `TUNIU_API_KEY_1`、`TUNIU_API_KEY_2`、`TUNIU_API_KEY_3`、`TUNIU_API_KEY_4`。用户确认这四个 Key 分别来自独立账号，因此每个账号独立计量。无需改动现有 Key 的内容，重启服务后生效。

实际新请求按 1→2→3→4→1 轮换。某个账号仍在请求中、间隔未到、额度用完或异常冷却时，先检查其他账号；普通间隔不足时等待剩余时间。各账号仍保留13秒启动间隔，滚动24小时的项目预算默认每账号40次，上限不超过官方50次。所有账号授权失败或长时间冷却时及时提示，不让任务无限等待。

命中缓存或相同在途请求合并时不发新请求，不推进实际调用轮换，也不消耗新配额。缓存与工具 schema 按账号分区，返回资料保留原查询槽位；原单Key模式仍可使用 `TUNIU_API_KEY`。存在编号Key时优先使用编号配置，旧字段不会额外加入第五个账号。重复Key去重。以后同一账号配置两个不同Key时，可把对应 `TUNIU_API_ACCOUNT_1` 等账号别名设为相同值，共享额度。

现有单账号调用记录保留：旧Key能对应某编号Key时沿用该账号历史，否则保守计入第一个账号，避免升级当天重置原用量。账号计数与冷却写入运行数据库的 calls 表，原始Key不写入数据库、日志、返回结果或 GitHub。失败调用保守保留用量，不跨账号自动重试同一次业务请求；后续新请求再使用其他可用账号。

外部连接及凭据调度已拆到 `app/integrations/`。业务继续使用 `providers.tuniu()` 和原来的只读白名单，未加入下单、取消或支付功能。酒店查询预算汇总各账号剩余额度，启动器也支持只有编号Key的配置。

官方参考：[会员与限制](https://open.tuniu.com/mcp/docs/guide/ratelimit.html)。同一账号的所有Key共享5次/分钟、50次/天；这不是承诺多账号能把所有规划操作加速四倍。

## 验证

- 全量374项后端测试通过。新调度测试使用隔离数据库和模拟时钟，覆盖轮换、冷却、配额、重复Key、同账号分组、旧记录、取消释放、缓存合并、密钥脱敏及只读白名单。
- 当前四个Key分别进行一次真实济南→青岛、2026-10-10的列车只读查询，均成功；单次2.50、1.74、1.44、1.22秒，合计约7秒，账号之间没有13秒强制等待。没有预订或修改用户旅行记录。
- 首次探测参数未匹配实时schema，修正后重测；失败探测用量保守保留，不重置计数。
- 启动器配置检查通过；文档导航相对链接核对通过。实时速度受网络和供应商响应影响。

## 目录整理

根目录保留 `.env`、配置模板、README、CONTEXT、依赖、测试设置和启动脚本。

| 位置 | 内容 |
| --- | --- |
| `app/` | 当前后端；`integrations/` 集中途牛连接、调度和工具白名单 |
| `frontend/` | 当前真实运行界面 |
| `docs/design/` | 产品结构、业务设计、项目方案和原型评审 |
| `docs/reference/` | 官方接口核对及途牛文档参考 |
| `docs/status/` | 开发状态历史记录 |
| `docs/collaboration/` | 组员分工和对接 |
| `docs/releases/` | 已完成更新及验证记录 |
| `prototypes/` | 旧HTML原型；误命名的 `.py` 副本保存为 `.py.html` |
| `scripts/`、`tests/` | 原启动与验证命令保留；补充用途导航 |
| `data/runtime/`、`output/`、`dist/` | 本地运行、汇报产物及体验包，继续忽略提交 |

全部移动文件保留内容，没有删除原型或用户数据；原路径的文档链接与迁移脚本同步修改。大型业务模块的旧导入路径保留，以便成员分支继续整合。
