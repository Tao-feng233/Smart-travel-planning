# 入住时刻先询问

日期：2026-10-09
分支：feat/shitu-v11-review-integration

## 问题与修复

旧时间轴在初步安排和正式计划转换时，都会给每晚已选酒店追加22:00酒店条目，并标记已确认。这个时刻没有来自用户，住宿位置选择也不代表确认办理入住的时刻。

已删除两处默认条目。选定酒店后，助手会询问入住时间是由用户自行安排，还是希望结合抵达和游玩行程先给出建议。主助手与计划模型提示明确区分酒店最早入住政策、用户计划到店时刻、前往/返回住宿的交通参考，未确认建议不写成已确认入住。用户说明的入住要求沿用现有hard_constraints保存。

抵达后的酒店接驳仍可用于道路核对，相关机动事件标为建议估计，不能当作确认入住预约。酒店位置、逐晚住宿日期和可选房型口径保留。计划书导出也说明入住时刻需要自行安排或讨论确认。

道路预览签名版本由2升级为3，旧缓存中默认22:00条目不再复用。已有对话中的历史文字不回写修改，重新展示时间轴即可使用新规则。
