# 动态时间轴与交通显示

日期：2026-10-09。基线：`feat/shitu-v11-review-integration @ 1a81941`。

## 页面变化

交通段单独显示起点与终点、步行/公交地铁/驾车打车参考方式、出发时刻、预计抵达、道路预计分钟数和额外缓冲。景点显示“建议游玩×分钟”，不与路程混用。车票标出班次交通方式及抵达日，跨日班次不把抵达当作当天23:59。出站、候车、安检单独标为准备区间。

还没有查路线时，时间轴先显示“交通方式/耗时待查询”，不虚构出发或抵达时间。用户可点击“核对交通时间”；选择变更后也会核对并更新时间轴。界面的“固定面板”仅控制面板显示位置。

## 模型工具

新增 `app/timeline_tools.py`，提供真正的模型function tool `adjust_timeline`，以及 `keep_timeline`。对话控制器也支持 `adjust_timeline` 动作。时间轴入口改为“智能调整时间轴”。

模型可提交已选景点的建议日期、顺序、游玩范围与时长、开始下限 `not_before`，以及合理的餐次时间/时长、午休及机动建议。工具验证ID、日期、用户固定安排、实际交通和关键时间衔接后才更新预览；非法方案不部分应用。最多一次带具体反馈的修订，自动修复有时间上限。

班次、景点选择、住宿、餐厅、用户固定日期/时段/顺序和旅行条件保留。模型不能自行改车票、删景点或编造交通分钟数。调整导致已有正式计划不一致时将其标为待更新，不声称已同步发布计划书。已有警告草稿也会绑定游玩安排，避免确认后恢复旧时间轴。

## 主动优化与提醒

排程遇到具体时段冲突时，将真实路段、剩余窗口和原建议时长交给工具助手，先尝试减少折返、调灵活日期/顺序、重新判断合理游览范围及餐次。左侧说明已经应用的调整。

普通负担不均和轻微超过建议结束时刻不再要求确认。程序通过估算超量幅度判断是否明显影响行程；目前超过约一小时且达到可用窗口的明显比例时才作为重要负担提醒，属于可调整的产品判断，不是官方标准。早于抵达、赶不上返程、违反用户固定时段和关键路线缺失仍单独说明。

时间轴审核助手继续只读，负责解释剩余严重风险；实际写入由调整工具完成。模型审核失败保留程序检查，不能使已经成功的选定操作失败。未查询的开放/道路仍标待核实，不能保证未来现场条件。

## 验证

354条后端测试通过。新增9个工具回归场景覆盖：真实function调用与道路反馈、调整后重新算路、固定选择保护、非法编辑回滚与一次修订、无查询不编造交通字段、轻微问题不弹警告、严重问题继续保留确认、已准备草稿随时间轴变化失效。

浏览器合成夹具验证点击工具入口会发送 `adjust_timeline`、更新开始时刻与游玩分钟数、显示实际交通方式和时间、未查路线不显示假时刻；回归推荐卡片、可选房型、逐晚住宿和诊断跳转。

合成示例的道路分钟数仅用于验证工具链路，不代表青岛实际路况。此次不会上传 `.env` 或用户旅行记录，也未扩展预算优化、MySQL或后台Worker。
