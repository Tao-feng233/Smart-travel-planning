# 推荐引导与住宿衔接修复

整合分支：`feat/shitu-v11-review-integration`。

## 本轮变化

- 住宿位置与报价状态分离：旧报价过期仍保留有效酒店坐标作为用餐和游览的路线起点。抵达后默认先前往已选酒店；到达日晚于或早于原查询覆盖期时提示入住、加住与费用待核实。出站接驳仍是建议时间，不声称已取得车站至酒店的完整路线。
- 首次一般性景点推荐先询问偏好，提供“暂无偏好，查看代表景点”入口。明确主题/地点查询及确认过的自动代选可以继续。现有数据没有真实热度指数，默认参考城市代表景点资料、地图评分与位置。
- 推荐模型收到明确的人数、儿童年龄、老人/行动需求和旅行日期内的天气；未知条件不补造。景点与餐厅卡片增加参考消费、参考人均、门票区间起价及有官方依据的免费入园提示。
- 对话与页面引导围绕当前操作：正在选景点时，说明“选择完成后，请补充……”，不再强制以“下一步”标题催促补齐。完成选择后再邀请补充对应查询所需的信息。操作入口及必要条件校验保留。

## 拉取后试用

按项目既有安装及启动方式运行。若原服务仍在运行，先在原启动窗口停止并重新启动，再刷新浏览器。旧旅行可以继续使用，但已有计划书需重新生成，历史消息不会自动改写。

建议复核：仅提供城市时的偏好询问及默认入口；选择景点过程中缺少日期/人数的引导；卡片价格提示；酒店报价过期后的早餐路线起点；提前一天抵达时的住宿提醒。具体房型仍可选，车票机票仍由用户自行选定。

验证：286 项后端测试通过；代选/诊断、可选房型、偏好入口及卡片价格浏览器夹具通过。本轮新增模型和供应商回归使用合成数据，不代表实时报价或库存保证。

`.env`、用户旅行记录和本地运行数据不包含在此次提交中。预算综合规划未在本轮扩展。

## 追加：午休、宽裕时间与完整景点推荐

- 午餐与午休分开安排。初步预留午休60分钟、景点间休息和机动30分钟；完成选择后的模型分析可结合同行人群、行动需求、天气及游览范围调整每日建议。明确说不安排午休或指定分钟数时采用用户要求。
- 临时时间轴、每日时间预算和正式计划书使用相同的午休建议，保留拍照、慢行、合理排队等游玩余量。就近休息，不默认已返回酒店或已有休息设施。交通限制压缩午休时显示提醒，密集估算继续走警告确认流程。
- 推荐数量由模型结合整趟游玩天数与停留时间判断，区分行程建议和备选；不再固定最多8个。每批最多24个是技术保护，每页4张卡片仅用于展示，较长行程可以继续补充。推荐并不代表已经选定或生成正式计划。
- “继续推荐一些”补充新候选，排除已展示或已选择的重复项，保留已有选择；暂未找到新结果时正常说明，不报安排错误。显式页码浏览继续使用原分页规则。

追加验证：294 项后端测试通过；浏览器已覆盖独立午休显示及继续推荐按钮的请求与选择保留。

## 追加：景区父子去重与交通时间轴

- 多级景区按已知地图父子链统一分组，八大关等地点不再同时出现在父景区列表和另一组标题中。父项标为景区范围介绍；选中父项与子项时保留选择，以具体子项合并安排，区域体验交给模型结合上下文估时，父项不再另加一整段游玩时间。
- 父项的明确日期/时段继续有效，矛盾安排提供父项和子项的定位提示。名称关联不作为删除游玩项的依据。旧计划书存在重复计时时需要重新生成。
- 时间轴显示住宿到景点、景点到餐厅、景点之间以及返回住宿的交通段，并把查询到的预计通行时间和缓冲计入时刻。点击路段可查看方式、预计耗时、缓冲及来源时间。
- 车站/机场主地点能唯一核对时补查与酒店的接驳。高铁/航班使用用户选定班次的出发和到达时刻；出站、退房、候车/安检仍是建议预留。无法唯一核对或网络未完成时明确待核实，不补造坐标和耗时。跨日接驳需单独确认。
- 时间轴道路预览复用正式排程器，不额外调用一次模型生成/审核；相关选择完成后更新，有效结果缓存15分钟。时刻为基于查询时道路与建议时长的预估，未承诺出游当天实时路况。

本轮验证：307 项后端测试；浏览器覆盖父子卡片去重、范围提示和交通段详情，另回归代选与可选房型。

已有旅行可在时间轴点击“核对交通时间”，只更新道路预览，不额外生成计划或改选内容。未知路段可通过“查看通行提醒”定位相关地点；正式计划书仍需用户发起生成或修订。
