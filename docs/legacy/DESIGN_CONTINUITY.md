# 设计思想延续与当前实现

## 延续的产品与工程原则

| 历史设计思想 | 当前实现 | 后续完善方向 |
| --- | --- | --- |
| 自然语言逐步收集需求，避免一次生成不可核验攻略 | 对话与旅行信息编辑共用工作区，保存日期、人数、偏好及候选选择 | 更完整的特殊条件与协商约束模型 |
| 模型负责理解和比较，事实通过工具和来源提供 | DeepSeek 意图识别、候选推荐；高德、途牛、和风及官方资料提供事实 | 日期规则库、来源覆盖评估与更细的证据映射 |
| 住宿、餐饮、景点与交通应形成完整旅行方案 | 景点、具体房型、往返班次、按日期餐次的餐厅、地图与计划书 | 站点接驳、多住宿分段、累计体力与行李安排 |
| 计划可行性与数据可信度应分别判断 | 候选与日期校验、路线时间计算、来源与查询时刻、未知项、独立审核 | 完整的数据就绪评估与状态模型 |
| 用户修改后应保留已确认内容 | 保留选择、按条件变更标记失效资源，旧计划标记待更新，支持撤销 | 锁定节点与最小范围局部重规划 |
| 地点事实与认知资料应区分使用 | 结构化接口事实与本地官方资料检索分别接入 | 资料扩充及基于失败样本评估语义检索 |
| 不公开密钥，不将模拟结果写为真实验证 | 密钥位于后端，本次仅提交空白配置模板；界面检查与真实接口核验分别说明 | 正式部署、监控及持续数据质量评估 |

## 历史方案的适用边界

历史文档中的 Vue 3、MySQL、Chroma、统一 v0.4 契约、三条开发线和 Mock/Hybrid 配置属于旧项目方案，未作为当前项目的运行前提。当前采用 FastAPI、两节点 LangGraph 主链、SQLite、纯 HTML/CSS/JavaScript 工作台和 TF-IDF 加关键词检索。

客流预测、完整预算核验、跨城多住宿、完整局部重规划和自动预订仍属于待完善或独立评估范围。历史文件中的已完成标记不作为当前版本的实现证明。
