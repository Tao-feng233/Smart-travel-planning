# 数据源可行性验证表

本表由成员A负责填写。当前不预设具体平台或API，先验证能否获取、字段是否够用、使用是否稳定，再决定真实接入、人工整理或模拟降级。

## 状态说明

```text
UNASSESSED    尚未验证
AVAILABLE     可稳定获取并满足P0字段
LIMITED       可获取但字段、范围、频率或权限有限
UNAVAILABLE   当前无法使用
MOCK_ONLY     项目演示只能使用fixture或模拟Provider
```

## 每个候选数据源的最小验证动作

1. 实际请求或打开一次，记录是否可访问。
2. 保存一条原始响应或页面截图。
3. 对照 `TRAVEL_GUIDE_SPEC.md` 检查字段是否够用。
4. 记录更新时间、频率限制和展示限制。
5. 写出Provider返回的统一示例JSON。
6. 判断失败时是否可以使用人工数据或fixture。

## 通过标准

一个数据类别只有满足以下条件才能标为 `AVAILABLE`：

- 至少完成一次实际获取。
- 可以映射到内部契约。
- 能说明来源和更新时间。
- 已知失败时怎样降级。
- 不需要让LLM自行补全关键事实。
