## FastAPI · 异步接口层

- 对外只有一个核心入口：聊天、查景点、选酒店、生成计划全走它
- 一次规划要**并发**查景点、路线、天气、酒店，异步避免串行等待

**为什么不用别的**

| 候选 | 不选的原因 |
|---|---|
| Flask | 同步为主，并发外部查询会串行等待 |
| Django | 自带 ORM 与后台整套，我们只需要轻量接口层 |
| 手写裸服务 | 路由、参数校验、接口文档都要自己造 |

**边界**：异步减少的是可并行请求的等待，**不等于每次规划都能立刻完成**。

---

## SSE · 单向持续推送

- 任务一提交，浏览器持续收到"正在查…"与分段回复
- 建立在普通 HTTP 上，浏览器原生支持、自带重连

**为什么不用别的**

| 候选 | 不选的原因 |
|---|---|
| WebSocket | 双向通道，我们只需服务端→浏览器一个方向 |
| 前端轮询 | 延迟高、无效请求多 |
| 一次性返回 | 规划动辄几十秒，用户会以为卡死 |

## LangGraph · 流程画成图

```
START → understand → check → execute → END
                      │
                      └─(不合格)→ 回到 understand 重来一次
```

| 节点 | 职责 |
|---|---|
| understand | 结合消息、旅行条件、已有选择，返回结构化意图 |
| check | 校验输出可用性；不合格带具体反馈**退回一次**，不无限重试 |
| execute | 校验真实 ID、日期、权限后，才执行 |

**为什么画成图**：可追踪、可定位——出问题时能分清是"理解错"还是"执行错"。

**须澄清**：景点、住宿、交通是**执行层业务动作**，不等于图中的独立节点。

## DeepSeek + Function Calling · 模型提案，程序把关

- 模型**不直接回答**，而是按约定格式返回"要做什么"（动作名 + 参数）
- 程序负责校验与执行：ID 是否真实、日期是否合法、是否被授权

**为什么这样设计**：业务**不依靠模型记忆**确认票价、路线或当天开放情况。

**决定权分级**

| 档位 | 是否需要确认 |
|---|---|
| 解释、回答 | 否 |
| 查询 | 否 |
| 保存用户明确选择 | 否 |
| **自动代选** | **必须先申请确认** |

**原则**：不把一次查询当成授权重排整趟旅行；**车票机票始终由用户自己确认**。

## 状态与并发 · 两层保护

| 层 | 机制 | 效果 |
|---|---|---|
| 互斥 | 有任务在跑时拒绝新修改 | 不并发写同一工作区 |
| 乐观并发 | 提交必须带版本号，不符返回 409 | **不静默覆盖** |

- 支持回来继续规划，版本可追溯
- 日期区分**用户输入 / 班次事实 / 系统建议**三种来源

## Repository 契约 · 先定接口，再写代码

5 个接口 + 日期语义，定死的是**语义**而非实现：

| 契约 | 定死了什么 |
|---|---|
| WorkspaceRepository | 按 owner 读取；**按 expected_revision 保存，冲突不能静默覆盖** |
| JobRepository | 幂等提交、互斥领取、租约、取消、完成/失败 |
| CacheRepository | 参数键、过期时间、查询结果 |
| ProviderBudgetRepository | 供应商额度**原子**申请与检查 |
| KnowledgeRepository | 原文/父块、doc_id、版本、来源、城市、适用时间 |

**取舍**：这一批**只交接口**，**不启用 MySQL、不迁移数据**。

## 我的三个设计决策

**1 · 模型提案，程序把关**
模型只给提案，执行前校验真实 ID、日期、权限；不过就带反馈退回一次。
代价：多一次调用。**收益：不会出现"计划里有个查无此地的景点"。**

**2 · 决定权分级**
解释 / 查询 / 保存 / 代选四档权限递增；代选必须先申请确认、可撤销。

**3 · 先定契约，再并行开发**
三人都要碰存储，先统一语义再开发，避免后期接口对不上的返工。

## 职责内遇到的问题与解决

| 遇到的问题 | 怎么解决的 |
|---|---|
| 两个请求同时改同一旅行，后提交的覆盖先提交的 | 加两层保护：有任务在跑时拒绝修改；提交必须带版本号，不符返回 409，**不静默覆盖** |
| 模型返回的动作引用了不存在的候选，或越权改了用户没授权的项 | 执行前校验真实 ID、日期、权限；check 节点不合格时带具体反馈**退回一次**，不无限重试 |
| 规划要几十秒，页面一直空白，用户以为卡死 | 改用 SSE 持续推送进度与分段回复，不再等全部完成才返回 |
| 三人各写一份存储/任务接口，合并时必然对不上 | 先出 Repository 契约与测试夹具，**只定语义不改业务**，三人照同一份开发 |
| 景点周边查不到餐厅时直接报"没有"或卡住 | 做三档退让：周边 5 公里 → 换关键词/放到 10 公里 → 城市范围，并**如实标注命中范围** |
| 页面资源版本表把依赖目录也算进去 | 改为只解析 `index.html` 实际引用的脚本与样式，按文件内容计算版本 |

**共同点**：这六项都不是"换个框架"解决的，而是**加约束、加校验、加回退路径**——
让系统在拿不到可靠结果时，也能给出明确反馈而不是静默出错。
