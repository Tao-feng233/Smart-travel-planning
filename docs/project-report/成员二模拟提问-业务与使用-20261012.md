# 模拟提问 · 老师追问业务与使用（含应答）

> 每题：【老师怎么问】→【答什么】→【别说】。
> 所有数字与机制均基于当前版本实测。**诚实口径反复出现，那是故意的**——
> 主动标注"没验证过"，比被追问出来体面得多。

---

## 第 1 轮 · 到底给谁用

**1. "具体是谁在用？给我描述一个真实用户，不要说'自由行用户'这种词。"**
**答**：三十岁上班族，带父母去青岛玩 3 天，住市南区，第一天下午 3 点才到。
他要同时兼顾老人体力、有限时间和不想折腾——这正是约束最多的场景。
**诚实**：没做过正式用户画像与调研。

**2. "他现在不用你的，用什么？哪里不够？"**
**答**：通用 AI 写攻略（不算道路耗时、不管首尾日、票价可能过期）、
小红书看别人的经验（日期/住宿位置/体力都对不上）、OTA 自己拼（只管订不管排）。
**别说**：别说"OTA 不帮你排"——OTA 已经有 AI 行程助手了。

**3. "一次完整规划要多久？用户愿意等吗？"**
**答**：几十秒，受供应商响应速度限制。用 SSE 推进度与分段回复，用户不用盯白屏。
**诚实**：**没统计过平均耗时**，不报数字。

**4. "用户得填多少信息才能开始？嫌麻烦走了怎么办？"**
**答**：只要**目的地 + 天数**就能开始；偏好可问可跳过，没偏好直接看代表景点。
关键变量（人数/天数/预算口径）事前确认，但不问完就不出方案是设计选择。

**5. "用户只说一句'我想出去玩'，能接住吗？"**
**答**：会先问目的地与天数——**不凭假设硬排**。这是"先问后做"的设计，
也是我们在实测里发现通用 AI 的短板（它只给一句就直接输出 3 天行程）。

**6. "中途改三次五次，会不会越改越乱？"**
**答**：不会。单一计划 + 版本号，改一处只动受影响部分并重新核对。
对比实测数据：通用 AI 一轮对话输出了 **4 套互相冲突的方案**。

**7. "老年人会用吗？界面这么复杂看得懂吗？"**
**答**：**诚实——没做过可用性/无障碍测试**，界面信息偏密集，这是已知不足。
**别说**：别说"我们界面很简洁"。

---

## 第 2 轮 · 使用流程与体验

**8. "用户就是不按你的步骤走，怎么办？"**
**答**：六步是**引导不是强制**。可跳过、可直接问别的、可只完成一部分就生成，
缺的部分标"待核实 / 自行安排"，不会卡住。

**9. "六步是不是太长？走到第三步就关页面了呢？"**
**答**：每步可跳过，住宿、车票、餐饮都不是必填。
**诚实**：**没有做过流失率统计**，不知道真实放弃率，不编数字。

**10. "计划书是打印带走还是手机看？支持手机吗？"**
**答**：支持页面打印与 Markdown 导出。
**诚实**：**没做移动端适配**，本期只做 Web，这是明确边界。

**11. "能分享给同行的人吗？一起改？"**
**答**：**多人协作没做**。当前是单用户工作区，按用户隔离。

**12. "出行当天到了现场发现不对，还能帮上忙吗？"**
**答**：计划书保留"出发前待办"提示出发前再确认；**当天的实时调整不在本期范围**。
**诚实**：我们不做实时导航与现场改行程。

**13. "旅行结束回来，这份计划还有用吗？"**
**答**：状态持久化，可回来继续规划或复用。
**诚实**：**没有做行程回顾 / 模板复用**这类功能。

**14. "断网了、页面关了，之前做的还在吗？"**
**答**：状态已持久化，重开可继续。
**但有边界**：**进程重启，运行中的任务不保留**（任务在进程内异步执行，不是独立 Worker）。

## 第 3 轮 · 结果敢不敢信（最狠）

**15. "用户怎么知道哪条能信、哪条不能信？"**
**答**：三档分离——**已有报价 / 参考估算 / 待核实**；每条带来源与查询时间。

**16. "标一堆'待核实'，用户还得自己去核实，那用你的意义是什么？"**
**答**：意义在**把不确定性摊开并压缩核对成本**。
实测人工逐条核对 16 项要 **40–50 分钟**，真实用户不会做；
我们把它收敛成一张"出发前待办"清单，让他知道**该核哪几项**，而不是整份都"看起来确定"。

**17. "按你的计划到了景点发现闭园，你们负责吗？"**
**答**：**不负责，也不能负责**——接口结果是**查询时快照**，不保证出游当天开放；
我们不做预订，也就**不掌握实时库存**。所以计划书明确列出待办。
**这句要说得坦荡**：这是产品定位的边界，不是推卸。

**18. "价格写'待核实'，不等于没给吗？"**
**答**：不是。关键是**区分"没有数据"与"数据为零"**——写"待核实"是不让用户以为免费；
已有报价（酒店起价、单人票价）会直接给出，且标注口径（起价≠总价）。

**19. "天气只覆盖预报窗口，提前一个月规划怎么办？"**
**答**：窗口外保留"未知"，**不编造**；天气缺失不会阻断其他规划步骤，会明确提示。

**20. "'建议时长'和实际差多少？差半小时就赶不上车了。"**
**答**：是建议值，受排队、体力、路况影响。
**诚实**：**没做过与实际耗时的偏差统计**。
能说的是：我们把道路耗时作为**查到的真实值**纳入衔接，并留缓冲。

**21. "你自己说不能消除幻觉，那我凭什么信你的系统？"**
**答**：**不靠"信"，靠"可核验"**——每条信息给来源与查询时间，用户可以自己查；
程序再校验真实 ID、日期、权限。这些是**降低风险**，不是消除。

## 第 4 轮 · 成本与运营

**22. "怎么赚钱？免费给人用，接口费谁出？"**
**答**：**没做过商业化评估**。可能方向：导购佣金 / 订阅 / B 端工具，均未验证。

**23. "一天多少用户能打平成本？"**
**答**：**没算过成本，不编数字。**

**24. "只有 20 个城市，用户去别的地方是不是用一次就不来了？"**
**答**：**对，这是当前最大边界**。扩展方式是往来源注册表加官方来源再重跑采集，
**不需要改代码**——瓶颈在**数据采购与整理**，不在架构。

**25. "接口额度用完了，用户看到什么？空白页？"**
**答**：**不会空白**。查不到就明确提示"未取得"，保留原有候选，
**不把"查不了"当零、也不当"查询成功但没有结果"**。额度会记录并在不足时停止。

**26. "供应商涨价或停服怎么办？系统不就瘫了？"**
**答**：会降级并明确提示。
**诚实**：**没有做多供应商容灾**——地图、天气、票务目前各只有一家，这是真实风险。

**27. "考虑过和旅行社、定制游合作吗？"**
**答**：没谈过。B 端是可能方向之一，未验证。

## 第 5 轮 · 凭什么是你

**28. "我打开 DeepSeek 问一句，比你们差在哪？说具体的。"**
**答**：三个具体差别——**数据有出处、道路真的算了、状态能延续**（单一计划+版本+局部修改）。
但对方接入工具也能拿数据，我们的重点是把这些能力**组织成规划闭环**。

**29. "携程也有 AI 行程助手，你们对比过吗？谁更准？"**
**答**：**没测过，不下结论**。我们实测的是通用 AI（16 项：准确 9 / 硬错 2 / 偏乐观 4）。
差异只讲**设计取向**：不绑库存的中立推荐、不确定性摊开、单一计划可局部修改。

**30. "小红书全是免费攻略，我为什么要打开你们？"**
**答**：攻略是**别人的**情况——别人的日期、住宿位置、体力，不能直接套用。
识途结合的是"你住哪、几点到、和谁去"。

**31. "腾讯、阿里做了，你们还有活路吗？"**
**答**：**没有能力和巨头比数据与流量**。但作为原型，我们验证的是
**这套流程设计是否成立**——约束核对、选择保留、不确定性表达，能不能真改善规划质量。

**32. "你的技术有壁垒吗？别人三个月能不能抄出来？"**
**答**：**目前没有强壁垒**，数据和技术都可复制，框架全开源。
真壁垒只会来自慢慢积累的三样：数据覆盖、编排质量、用户行程数据。

**33. "是不是就是把几个 API 串起来？"**
**答**：数据确实来自外部接口，但重点不在调接口，而在
**把查询结果、用户选择和约束检查组织成可执行、可修改的计划**——
例如把班次抵达、接驳准备、景点时长、餐次休息、道路耗时连起来算可用窗口。

## 第 6 轮 · 压力质疑

**34. "三个人做几个月，和市面上免费的有本质区别吗？"**
**答**：**没有代际差别**。差别是可核验、可复算、单一计划状态、不确定表达——
这些都是**工程细节**上的差别。我们不做夸大。

**35. "'不把估算包装成保证'——用户要的就是确定答案，你们是不是在逃避？"**
**答**：**不是逃避**。把"不知道"标出来，是让用户知道**该去确认哪几项**；
如果把估算说成确定，用户现场出一次错就不会再信——**诚实反而是信任的基础**。

**36. "这个项目最大的失败风险是什么？"**
**答**：两条——① 数据覆盖做不上量（瓶颈在采购不在架构）；
② 用户不愿为"排"付费，因为这个需求离交易远、感知价值弱。

**37. "再给三个月，你会做成什么样？"**
**答**：用户调研 → 数据覆盖扩展 → 路线顺序优化算法（道路数据现成） →
前端组件化 + MySQL / 独立 Worker。列能验证、能落地的事。

**38. "打个分，为什么不是满分？"**
**答**：闭环跑通，但工程成熟度差得远——没压测、没用户调研、只有 20 城、
任务不是独立 Worker、移动端没做。全部写在边界里。

**39. "哪些是真正你一个人独立做的？说细一点，别讲团队成果。"**
**答**：我独立完成的——存储与任务契约（含测试夹具）、业务动作执行与校验流程、
决定权分级设计、餐饮 0 候选兜底与范围标注、计划书可视化与前端分层。
**不属于我**：MCP 与供应商封装（协调者）、RAG 检索（成员一）、排程与冲突检查（成员三）。
**别说**：别把团队成果说成自己的，也别把自己做的说成"参与了一下"。
